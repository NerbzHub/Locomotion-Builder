# Preface

This document defines the official construction schedule for the Locomotion Builder.

Its purpose is to organise implementation into a sequence of deterministic engineering sprints.

Each sprint has a single primary objective.

Sprints are intentionally small, independently verifiable and designed to be completed in sequence.

Completion of a sprint should leave the Builder in a stable, runnable and checkpointable state wherever practical.

This document defines **what** is constructed.

It does not describe **how** individual features are implemented.

---

# Construction Principles

The Builder shall be constructed according to the following principles.

* One primary objective per sprint.
* Every sprint produces measurable progress.
* Every sprint concludes with validation.
* Every sprint concludes with a checkpoint.
* Construction proceeds sequentially.
* Earlier sprints establish foundations for later work.
* No sprint should require speculative future implementation.

# Construction Rules

The following rules apply throughout construction.

* Construction proceeds sequentially.
* Completed sprints should not be revisited without formal justification.
* Every sprint concludes with validation.
* Every version concludes with a version validation sprint.
* Checkpoints should be created regularly.
* Engineering documentation remains the authoritative source throughout construction.
* Implementation should always conform to the Constitution and Conceptual Architecture.

---

# Completion Criteria

The Locomotion Builder Version 1.0.0 is considered complete when:

* all scheduled sprints have been completed
* Workspace persistence is reliable
* construction can be resumed safely
* Jobs coordinate all engineering operations
* engineering history is maintained
* checkpoints are functional
* construction progress is observable
* validation workflows operate correctly
* the Builder is capable of orchestrating the deterministic construction of a software project from commencement through completion

---

# Closing Statement

This Construction Schedule defines the official implementation sequence for the Locomotion Builder.

It provides a deterministic roadmap for engineering progression while remaining independent of implementation technologies.

Future versions may extend this schedule through additional phases and sprints, but they should preserve the same engineering discipline: small, verifiable increments built upon stable foundations, resulting in a Builder that remains maintainable, recoverable and dependable throughout its lifetime.
